# Matched-image passing follow-up

The author and Gemini 3.1 Flash-Lite chose among three legal receivers on 16 fresh boards. They saw the same PNG, coordinate roster, task, rules and options on each board. The author could remember prior questions in a continuous quiz. Gemini received each question in a fresh context with a 4,096-token limit. The single author had already seen the earlier study results. [Original design and collection instructions](protocol.md)

## Reproduce the results

Run this command from the repository's `benchmarks/paired-positions/` directory using Node.js 24.2 or later. It runs offline using the Node.js standard library.

```sh
node anc/followup/reproduce.mjs
```

The command regenerates the bank from seed 274196013, excludes geometric repeats against the original pass bank, and compares every generated byte with the frozen bank. It uses the sibling [rules-22 engine](../native/engine.mjs) to value all 48 offered passes and replay 328 legal tackle landings at both test rolls. It rebuilds the 16 serialized model requests from the exact prompts and PNGs and verifies their SHA-256 digests. It then scores both sets of choices, lists the outcome of each pair and counts knight choices. The input data are the [board keys and pair definitions](bank.json) and [decoded choices in quiz order](comparison.json).

| Measure | Author | Gemini 3.1 Flash-Lite |
| --- | ---: | ---: |
| Valid decisions | 16/16 | 16/16 |
| Optimal receiver | 15/16 | 7/16 |
| Both boards in a pair correct | 7/8 | 2/8 |
| Receiver changed on switch pairs | 4/4 | 2/4 |
| Receiver changed on stay pairs | 1/4 | 1/4 |
| Mean retention loss | 3.125 percentage points | 28.125 percentage points |

Both solved two pairs, the author alone solved five, Gemini alone solved zero, and neither solved one. In a post hoc count, the author chose the knight on five boards and Gemini on 13. The knight was optimal on four boards.

The scorer also reports a post hoc Gemini comparison across the two pass banks. On boards with an exposed knight (retention 0.5), one safe ordinary receiver (1), and one exposed ordinary receiver (0), Gemini selected the safe receiver on 18/19 original boards and 3/12 follow-up boards. It chose the knight on the remaining 1/19 and 9/12. Board selection and presentation changed across the two studies.

## Post hoc value of observing the edited defender

Run `node anc/followup/value-of-information.mjs` from `benchmarks/paired-positions/`. Suppose the pair is known, its two boards are equally likely, and the decision-maker knows the engine value of every offered action on both boards. Revealing the member lets the decision-maker choose the best action separately on each board. With the member hidden, it chooses the action with the highest average value across the pair. The script reports the difference in percentage points for switch pairs, stay pairs and each complete bank. It also verifies that removing the edited defender makes the two observations identical within each pair and that these masked observations are distinct across pairs in each bank. The resulting calculation measures the value of resolving this particular uncertainty under the specified prior.

## Participant materials

Open [the original quiz](participant/quiz.html) with the adjacent `images/` directory intact. The quiz shows one board at a time and locks each confirmed choice. The [manifest](participant/items.json) lists the original order, exact prompt text, menu, image name and text/image hashes. The frozen [request builder](model.mjs) combines the prompt and PNG into one model request. It specifies temperature zero, high thinking and a JSON integer choice. The [renderer](build-quiz.py) and [HTML template](quiz-template.html) are included. Exact raster regeneration can depend on the local font and Pillow version. The archived PNGs are the images used at collection.

## Provenance

The [local freeze](freeze.json) was recorded at 19:22:14 UTC on November 27, 2026. It includes digests of the materials, scoring code and requests. A local collection receipt recorded 16 completions at 19:32:03 UTC that day and the SHA-256 of this freeze. The [comparison record](comparison.json) includes the SHA-256 of that receipt, the author’s submitted code, the model alias returned on all 16 calls and the one-based decoded decisions. During release preparation, all 16 original response-envelope digests were checked against the receipt and all 16 model choices were re-parsed from those envelopes. The public scorer starts from the decoded choices.

The bank, freeze, model request builder, comparison record, quiz, manifest, PNGs, renderer and template retain their original bytes. The public package adapts three sources from the historical freeze.

- [bank.mjs](bank.mjs) has three shorter relative paths to the same engine and original-bank files. The verifier restores the original path strings in memory and checks the pre-response source digest.
- [score.mjs](score.mjs) contains the original scorer’s `score` function. [reproduce.mjs](reproduce.mjs) reads decoded choices, verifies the participant materials and checks the resulting scores against the recorded comparison.
- [protocol.md](protocol.md) retains the original design, collection instructions and endpoints. Its final section now gives the public offline scoring command.
